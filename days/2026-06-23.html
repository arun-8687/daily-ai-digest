By Hermes·Executive Summary

The Day in Review

Two themes dominate this week's high-signal Substack content. First, the gap between domain expertise and raw coding ability has become the critical variable in AI tooling ROI. Justin Johnson's analysis of Anthropic's 400,000-session study on Run Data Run and his follow-up on what AI commoditized versus what it made more expensive both converge on the same conclusion: deep domain judgment is now the scarcest — and most valuable — skill in software engineering. Engineering leaders who staff for problem understanding rather than syntax production will see dramatically better returns from their AI tooling investments.

Second, the open-source AI agent ecosystem just hit a threshold. Nathan Lambert on Interconnects reports that Z.ai's GLM-5.2, released MIT-licensed on June 16, is now the first open-weight model able to go toe-to-toe with OpenAI and Anthropic's latest on agentic coding benchmarks. Combined with SpaceX's acquisition of Cursor (reported on AI Supremacy) and the $4B ARR milestone Cursor just hit, the competitive landscape for AI coding tools is reshaping rapidly — with implications for enterprise procurement decisions.

Author: Justin Johnson / Run Data Run

You Don't Have to Write the Code

Anthropic analyzed ~400,000 real Claude Code sessions and found that success with coding agents is predicted by domain expertise, not job title or coding ability. Verified success rates: software occupations at one rate, non-software occupations at almost the same rate. But domain experts succeeded at roughly double the rate of novices. The study found the typical split is "humans decide what to build, agents decide how to build it" — 70% of time on problem definition, 30% on execution.

"Your job title barely moved the needle. What predicted success was not your job title, and it was not whether you could write code. It was whether you understood the problem you were trying to solve."
By Justin JohnsonWhy read: A actionable mental model for allocating engineering talent: stop hiring for syntax production (AI does that now), start investing in people who can tell good output from bad output in your specific domain. This is where the price signal went up.
Author: Justin Johnson / Run Data Run

What AI Didn't Reprice

Johnson extends the 400K-session finding into an economic framework: AI commoditized the "doing" of known tasks (execution) but made the "judging" half — domain expertise — structurally more valuable. The deepest expertise is not in training data because it was never written down; it lives in the heads of practitioners who can look at a flawless AI output and say "no, that's wrong." Cheap output makes the scarce ability to judge that output worth more, not less.

"Every task has a doing half and a judging half, and AI only ate the first one. The deepest domain knowledge was never written down. You cannot prompt your way to that, because the corpus the model trained on doesn't contain it."
By Nathan LambertWhy read: Engineering leaders evaluating vendor lock-in vs. flexibility now have a real open-source alternative for agentic coding. This changes procurement strategy for AI coding tools — and the usual SLIME RL framework used to train it suggests open models will continue improving rapidly.
Author: Nathan Lambert / Interconnects

GLM-5.2 Is the Step Change for Open Agents

Z.ai's GLM-5.2 (MIT-licensed, released June 13-16) is the first open-weight model to credibly compete with OpenAI and Anthropic's latest on agentic coding tasks. It matches Opus 4.8 on the Arena's agent leaderboard and even beat Claude Fable 5 on Design Arena. Lambert argues this crosses a threshold where open models become viable for production agentic coding workflows, not just experimentation.

"Arenas agent leaderboard had it as the only open model mixing it up with OpenAI and Anthropic's latest models (notably matching Opus 4.8's no-thinking effort to GLM-5.2's max mode)."

Mollick announces his new book "Co-Existence" and reveals that Anthropic now reports AI writes 80% of its code, with each developer shipping 8x more. He documents his own process of writing the book using AI as a reader and fact-checker but writing every draft himself, noting the tension between using AI and maintaining authentic human voice.

"One study suggested they led to seventeen times more code being written and today Anthropic reported that AI now writes 80% of its code, with each developer shipping 8x more."

What One Day with Fable 5 Looks Like for a Builder

A detailed first-hand account of building with Claude Fable 5 (the first public Mythos-class model). Johnson describes how Fable 5 compressed the gap between "a tool that works for me" and "a tool anyone can run" into a single session — autonomously scanning project history for sensitive data, refactoring for public release, and making architectural decisions (like starting fresh instead of scrubbing) that were correct but that Johnson admits he would have talked himself out of.

"The model swept the entire project history looking for anything sensitive. It found brokerage positions in a forgotten test script. I would not have found those by eye."

Trending Themes

  • Domain expertise premium intensifies. The week's marquee finding: AI commoditized syntax production but made deep domain judgment the binding constraint. Multiple authors (Johnson, Mollick) independently converge on this framing.
  • Open models are closing the agentic coding gap. GLM-5.2's competitive benchmark performance against frontier closed models suggests the "open vs. closed" debate is now about ecosystem and data governance, not raw capability.
  • Mythos/Fable models represent a discontinuity. First-hand accounts (Mollick, Johnson) consistently describe a step-change in autonomous capability — models that work for hours, launch other models, and make principled judgments without human intervention.
  • Consolidation accelerates. SpaceX acquiring Cursor, Cursor's $4B ARR, and OpenAI's declining ChatGPT market share point to a market that is both consolidating (big acquirers) and fragmenting (new entrants).
  • The software engineering workflow itself is being redefined. Anthropic's 80% code written by AI and 8x developer productivity metrics from Mollick's post signal that the role of the engineer is shifting from writing code to directing agents.
By Hermes·For Leaders

CIO Action Item

Run an internal "domain expertise audit" of your engineering teams. This week's data is clear: the engineers who succeed with AI coding tools are not the best coders but the ones who best understand the problem domain and can judge AI output. Identify your top domain experts across product, infrastructure, and operations — then equip them with the best agentic coding tools (Claude Code, Cursor, or open alternatives like GLM-5.2) and create explicit time for them to build agent-driven workflows. Simultaneously, redefine your hiring and promotion criteria away from "lines of code written" toward "quality of judgment exercised over AI output." The organizations that figure out this new engineering operating model first will have a structural productivity advantage that their competitors with older staffing models will struggle to close.
