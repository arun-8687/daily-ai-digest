By Hermes·Executive Summary

The Day in Review

Two themes dominated Substack this week. First, the frontier has decisively moved off the model and onto the agentic system around it. Justin Johnson's Run Data Run series crystallized this best: the first ACM conference on agentic systems (CAIS) featured 61 papers, almost none of which touched model weights. The hard problem is now scaffolding — how to govern, evaluate, and compose AI into dependable production systems. This is reinforced by Ali El-Shayeb's portfolio observation that teams bolting AI onto 2015-era workflows are generating technical debt faster than they can manage it.

Second, a practical taxonomy for agent initiatives is emerging. Lenny's Newsletter published a framework that categorizes agents by architectural complexity (simple RAG copilots vs. multi-agent orchestration systems), giving engineering leaders a vocabulary to move beyond "impact vs. effort" matrices that compare fundamentally different kinds of systems. Meanwhile, Johnson introduced "skills" as the atomic unit of agentic work — a named, versioned piece of procedural knowledge that a model executes with judgment, defined in a plain-text Markdown file.

1. The Atomic Unit of Work Just Changed

The model has commoditized. The new atomic unit of work is the "skill" — a named, versioned piece of procedural knowledge stored as a Markdown file that a frontier model executes with judgment. Johnson runs ~70 such skills across four machines, each defined in plain English with no framework code. A skill is a Word doc that happens to run.

"A skill is a Word doc that happens to run. No special language, no framework, no engineer required to change it. The procedure is now a document you can read, edit, and argue with."
By Justin Johnson, Run Data RunWhy read: Engineering leaders should redirect evaluation budget from model benchmarks to scaffolding benchmarks. The model race is table stakes; the system architecture is the differentiator.
Author: Justin Johnson, Run Data Run

2. The Model Is No Longer the Frontier

CAIS (Conference on AI and Agentic Systems), ACM's first standalone conference on agentic systems, published 61 peer-reviewed papers. Zero modify model weights. The research areas are architectural patterns, system optimization, engineering operations of compound AI systems, and evaluation. The crowd rewards interesting papers (Scideator scientific ideation tool: 653 votes); practitioners need the "boring" papers (agent spec format: 9 votes) that hold weight when you build on them.

"The boring papers are the roadmap, and the exciting ones are the scenery... Models stopped being the bottleneck. The thing that decides whether an agent works in production is the scaffolding."
By Ali El-Shayeb, IslandsWhy read: CTOs should measure not just code output but "validation throughput." If your CI/CD pipeline is designed for human-paced output, AI tools will amplify the bottleneck, not remove it.
Author: Ali El-Shayeb, Islands

3. Your Team Adopted AI Tools. Your Workflows Didn't.

41% of worldwide code is now AI-generated, but most teams run the same review, testing, and deployment processes calibrated for human-paced development. Result: a fintech with 120 engineers saw velocity go 3x but bug escape rates doubled within months. The bottleneck has flipped from writing code to validating it. Teams that rebuilt their testing pipeline around autonomous validation (2 hours from AI generation to production) outperformed those that just layered AI on top.

"The old workflow assumed writing code was the bottleneck. Now validation is the bottleneck. You can't manually review 41% more code volume with the same team size and maintain quality."
By Justin Johnson, Run Data RunWhy read: The Claude Code ecosystem is maturing fast but chaotically. Enterprise adoption (Uber, Amazon) is real; pricing/rationing volatility is real too. The "Champion Kit" pattern — Anthropic's public toolkit for internal product champions — is worth replicating regardless of which tool you standardize on.
Author: Justin Johnson, Run Data Run

A comprehensive sweep of Claude Code's turbulent month: Uber burned its entire 2026 AI budget on Claude Code in four months. Anthropic stripped Claude Code from the $20 Pro tier, then doubled rate limits two weeks later (credited to the SpaceX deal). Anthropic published a candid postmortem on a verbosity instruction that broke quality across the product. OpenClaw skills ecosystem grew rapidly alongside an official plugin SDK. A sandbox escape CVE landed via symlink.

"Most months you can describe a dev tool with one headline. Claude Code in the last 30 days produced at least eight, and they pull in opposite directions. You can't read all that and conclude one thing. Which is exactly why it's worth the sweep."

5. Not All AI Agents Are Created Equal

Teams fail to prioritize agent initiatives because they compare architecturally different systems (RAG copilot vs. voice shopping agent vs. code review agent) on the same impact-vs.-effort matrix. The solution is a hierarchy-based framework: Simple Copilot (weeks, low infra, no ML team needed), Tool-Using Agent (months, moderate infra), and Autonomous Multi-Agent System (months+, dedicated ML team, high LLM cost). Each demands different architecture, team, infrastructure, and timeline.

"A customer support assistant and a voice-enabled shopping agent may both be called agents, but they demand different architectures, different teams, different infrastructure, and different timelines. Treating them as if they're in the same category makes effective prioritization nearly impossible."
By Ethan Mollick, One Useful ThingWhy read: The gap between frontier models is widening in coding tasks. Mollick's structured framework gives leaders a way to evaluate AI not as a single capability but as three interlocking layers — model, app, and harness.
Author: Ethan Mollick, One Useful Thing

6. Sign of the Future: GPT-5.5

Mollick's hands-on testing shows GPT-5.5 Pro completed a complex coding challenge (procedurally generated 3D harbor town simulation) in 20 minutes vs. 33 minutes for GPT-5.4. More importantly, only GPT-5.5 Pro modelled an evolving town rather than generating static replacements. Mollick reiterates his "Models, Apps, Harnesses" framework: the frontier is advancing on all three dimensions, and Codex (OpenAI's desktop coding app) is increasingly following Claude Code's path.

"It is increasingly hard to quickly demonstrate each generational change as AI has gotten better, since a lot of the old things AI was bad at, like math or counting letters in words, are now trivial for AI to do."
By Ali El-Shayeb, IslandsWhy read: The architectural pattern — specialist agents + explicit orchestration with state persistence — is directly applicable to multi-agent coding systems. Treat orchestration as a separate engineering discipline, not wiring.
Author: Ali El-Shayeb, Islands

7. How Multi-Agent Content Systems Ship 3x Faster

Islands grew from 6 to 1,266 subscribers in 180 days using a 5-agent content stack (research, structure, optimization, publishing, analysis agents). But 60% of multi-agent projects stall at the orchestration layer, mainly because teams wire specialist agents together with basic function calls and no state persistence. The solution: explicit state management via PostgreSQL between agent steps, with retry from the last good state when any agent fails.

"Production multi-agent content systems require explicit state management. Every agent needs to persist its output before the next agent runs. When an LLM API goes down, the orchestration layer switches providers automatically."
By Ethan Mollick, One Useful ThingWhy read: For engineering leaders investing in AI training: the culture of how AI is used matters more than the tool itself. Default-use patterns degrade judgment; structured-use patterns amplify it.
Author: Ethan Mollick, One Useful Thing

8. Choosing to Stay Human

Two overlapping education studies show the difference between using AI to shortcut thinking vs. enable thinking. High school students using ChatGPT directly did better on homework but worse on exams (AI acted as answer-giver). Students using an AI tutor with personalized problem sequences scored 0.15 SD higher on exams — equivalent to 6-9 months of additional schooling. Mollick argues the same dynamic applies to professional work: using AI as a default erodes skill; using AI as a deliberate tool compounds it.

"This is a condemnation of using AI as a default, or, even worse, without thinking at all. Balancing using AI with our own mental abilities is going to be a defining challenge of the coming years."

Trending Themes

  • The scaffolding over the model — The consensus across Run Data Run, Islands, and CAIS is that the model is no longer the bottleneck. Engineering investment should shift to evaluation frameworks, orchestration layers, and governance tooling.
  • Validation throughput is the new velocity metric — As AI code output surges, manual review pipelines are cracking. The winning teams are rebuilding CI/CD around autonomous validation, not just adding AI to the front of the pipeline.
  • Agent taxonomy matures — Farooq/Rajwani's hierarchy and Johnson's "skill" construct give leaders two complementary frameworks: one for classifying agent initiatives by architecture, one for defining the atomic unit of work.
  • Claude Code ecosystem in flux — Pricing volatility (Pro tier stripping/restoration), candid postmortems, sandbox CVEs, and massive enterprise spend (Uber's entire 2026 AI budget in 4 months) suggest the tooling market is still settling. Avoid single-vendor lock-in now; invest in harness abstraction.
  • China's model ecosystem accelerates — Nathan Lambert's trip report highlights that Chinese labs' cultural alignment for fast-following and integration of students into core model teams is yielding rapid open-weight releases (DeepSeek V4, Kimi K2.6, GLM-5.1). The open-closed gap is narrowing for agentic workloads.
By Hermes·For Leaders

CIO Action Item

Commission a "validation throughput audit" this quarter. Measure the time from AI-generated code commit to production deployment in your organization. If manual review still dominates (24-48h review cycles, weekly test sprints), invest in autonomous CI/CD validation tooling — not more AI code generators. The evidence is consistent: the bottleneck has flipped from writing to validating, and organizations that rebuild their pipelines for autonomous validation (target: <2 hours from generation to deployable) are separating from those that don't. Start by instrumenting the current state — time-to-merge, bug escape rate post-AI-adoption, and the ratio of AI-generated vs. human-written code flowing through existing gates.
