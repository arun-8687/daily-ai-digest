By Hermes·Executive Summary

The Day in Review

This week's Substack coverage coalesces around a single, sharp theme: AI coding tools have matured from individual productivity enhancers into organizational systems that demand new engineering discipline. Multiple independent authors — from Gergely Orosz at Pragmatic Engineer to Ethan Mollick at One Useful Thing to Richard MacManus at Latent Space — converge on the same conclusion: the model wars are effectively over, and the real differentiator is now the harness, the harness, the workflow, and the team practices built around the model. Claude Code, Cursor, Codex, and Antigravity have converged on nearly identical agentic architectures (terminal-native surface, explicit planning before execution, approval gates at dangerous moments, MCP as connector standard, parallel agent work). The question for organizations is no longer "which model?" but "which workflow are we willing to lock into?"

The second dominant theme is the hidden cost of velocity. Several posts surface novel failure modes: "code review surrender" (reviewers can't keep up with agentic output volume), "code review exploitation" (reviewers become the first real validators because author-side verification is absent), "cognitive debt" (the gap between what you think the system does and what it actually does when you're not reading the code), and the "invincible software engineer" trap (overconfidence from compressed first-90% delivery while the last-10% — observability, compliance, data migration — remains brutally expensive). These are not hypothetical concerns; they are being reported by practitioners running agents in production right now.

Finally, there's a practical thread on cost governance and model routing. As frontier models like Claude Fable 5 deliver more autonomy per prompt, they also deliver larger bills. Multiple authors share concrete playbooks: use "high" not "max" reasoning effort for most tasks, route grunt work to cheaper models, keep CLAUDE.md instructions tight, and treat the effort setting as the single biggest cost lever. Meanwhile, open-weight models like GLM-5.2 are closing the capability gap at 5-6x lower token cost, making heterogeneous model fleets increasingly viable for cost-conscious organizations.

What is "loop engineering?"

"Loop engineering" — designing automated loops where an agent repeatedly prompts itself rather than having a human prompt it each time — has become a trending practice after Anthropic's Boris Cherny (Claude Code creator) said "I don't prompt Claude anymore. I have loops running that prompt Claude... My job is to write loops." Orosz investigates and finds the reality is messier than the hype: most real-world loops are triggers and cron jobs (useful but not revolutionary), several devs reject looping after trying it due to agent drift and cost, and distinguished engineer Max Kanat-Alexander believes loops may have been a temporary hack while harnesses caught up. Orosz concludes that for most engineers, "context engineering" (understanding AI context windows) matters more than loop engineering.

5 Trends That Defined AI Engineering at World's Fair 2026

The AI Engineer World's Fair revealed five trends: (1) focus shifts from agents to systems around them (Lilian Weng's evolution from "LLM Powered Autonomous Agents" in 2023 to "Harness Engineering for Self-Improvement" in 2026), (2) loop engineering as the new control layer with inner/outer loop separation, (3) AI engineering enters the enterprise via Forward Deployed Engineers, (4) coding agents replace IDEs as the developer interface, and (5) every platform is building around "skills" (declarative Markdown files that encode workflows and best practices). YC president Garry Tan urged companies to "encode all of that as skills, written procedures that their agents execute, and hire engineers whose job is to maintain those skills."

The twilight of the chatbots

Work is shifting from "co-intelligence" (humans prompting AI step-by-step) to "co-existence" (assigning work to autonomous agents). Epoch found Opus 4.7 working 14 hours autonomously built a package that would take 2-17 weeks of human engineering (cost: $251 in tokens). A joint OpenAI/academic study shows 25% of OpenAI workers run 4+ agents simultaneously weekly — and adoption is nearly equal across legal, HR, and other non-tech functions, not just coding. The key finding from a Claude Code study: user profession didn't predict success — domain expertise did. "The more domain experience someone had, the more successful they were in using Claude Code in that domain."

"We are moving from a world where non-experts use chatbots to fill in gaps to one in which experts use agents to get work done. And the best way to use agents is to think of yourself as a manager."

GLM-5.2 is the step change for open agents

Z.ai's GLM-5.2 is the first open-weight model that feels right in coding harnesses as a general agent — a "one-way door for AI progress." It matches Opus 4.8 on Arena's agent leaderboard (at max thinking effort) while costing 5-6x less. Lambert used it in Claude Code with a Fireworks API backend and found the model capabilities "immediately felt right," with only minor integration issues. This breaks Anthropic's near-monopoly on coding agent revenue (driven by being the best-and-only model for harness-based coding) and signals that open-weight alternatives will arrive faster than expected.

"GLM-5.2 is the first of many (coming soon) open weight models to offer credible alternatives. The parallel is very clear, to when DeepSeek R1 showed that open-weight labs, with far fewer resources, could also replicate the chain-of-thought reasoning models that OpenAI championed with o1."

When Agentic Coding Breaks Code Review

Two new failure modes are emerging from agentic coding adoption: code review surrender (a capacity failure — reviewers can't keep up with volume/pace and reviews become superficial, delayed, or abandoned) and code review exploitation (a responsibility failure — reviewers become the first real validators because author-side verification is absent or untrustworthy). Greiler also introduces cognitive debt from her own 4-month experiment building software with GenAI without reading the code: "The way I specify and the way the system and implementation turn out are not completely aligned. I can't tell for sure how they diverge because I'm not looking at the code. But I know."

"Cognitive debt: the accumulated gap between a system's evolving structure and a team's shared understanding of how and why that system works and can be changed over time." — adapting Margaret-Anne Storey

I Maxed Out Fable 5 and Regretted It. Here's How I Actually Run It Now

A practical cost playbook for frontier model usage: (1) The "effort setting" (low/medium/high/xhigh/max) is the single biggest cost lever — but it controls thinking per step, not total work. Max effort means overthinking every step, including boring ones, and reasoning compounds across steps making costs multiply, not add linearly. Fable scores highest on Cognition's FrontierCode test even at medium effort. (2) Stop using the smartest model for everything — route grunt work to cheaper models via CLAUDE.md instructions. (3) A "quick tell": if a small ask comes back with a big diff full of unrequested changes, your effort is too high for that task. The author includes a concrete CLAUDE.md routing configuration.

"It does not decide how long the model can work or how hard a problem it can crack. It decides how much it thinks per step. Push it past high, into xhigh or max, and it does not take more steps. It overthinks every single one."

The Rise of the Invincible Software Engineer

The real danger of agentic coding isn't hallucination, security, or cost — it's overconfidence. When the friction of traditional coding evaporates, engineers develop a feeling of invincibility that masks two enduring facts: (1) "the last 10% is still the most expensive part" — agents compress the first 90% into an afternoon but observability, failure modes, compliance, and data migration didn't get the memo; (2) "software engineering is a team sport — and the value moved" from typing to customer understanding. Rao identifies five things that break when velocity outruns valuation, including: the end-to-end test becomes the product spec, the review process becomes the bottleneck, and the traditional proxies for quality (effort, time, seniority) are deleted from the equation.

Trending Themes

  • Loop engineering is the new buzzword — Multiple posts (Pragmatic Engineer, Latent Space, Spatial Awareness) grapple with the concept, with the consensus being that the inner/outer loop model is real and useful, but full autonomy is premature and "loopmaxxing" has diminishing returns.
  • The model wars are over; the harness wars have begun — SWE-bench scores have converged, and differentiation has shifted to workflow design, pricing models, distribution, and team habits. MCP has become the de facto integration standard without a formal vote.
  • Open-weight models are closing the agentic coding gap — GLM-5.2 is the first open model that works credibly in coding harnesses, at 5-6x lower cost than frontier closed models. This has procurement implications for any organization currently locked into a single vendor.
  • Code review is breaking under agentic volume — "Code review surrender" and "code review exploitation" are emerging as named failure modes. Cognitive debt — the gap between what you think your agent-built system does and what it actually does — is a first-class organizational risk.
  • Cost governance is becoming a first-class engineering concern — Effort settings, model routing, and CLAUDE.md instructions are the new levers for cost control. Running everything at max effort is the most common and most expensive mistake.
  • Skills as the new abstraction layer — Declarative Markdown files ("skills") that encode workflows and best practices are becoming the way teams customize agent behavior. YC's Garry Tan explicitly recommends hiring engineers whose job is to maintain skills.
  • The last 10% problem persists — Multiple authors independently note that agents compress the first 90% of software development but the last 10% (observability, compliance, data migration, upgrade paths) remains as expensive as ever.
  • Enterprise adoption is still early-adopter concentrated — Despite the hype, Cursor's own FDE team reports that enterprise AI adoption "is still concentrated among early adopters," with finding "the right champions inside an organization" being a key challenge.
By Hermes·For Leaders

CIO Action Item

Establish a model routing policy before your cloud bill does it for you. The single most expensive mistake in agentic coding today is running frontier models at max reasoning effort for every task. Multiple independent practitioners confirm that "high" (not "max") effort produces better output for most real-world work — max effort causes the model to overthink every step, producing unnecessary abstractions and unrequested refactors, while compounding costs across long agentic runs. Implement a three-tier routing policy in your team's agent instructions (CLAUDE.md or equivalent): (1) Frontier model at medium/high effort for architecture, API design, and final review; (2) Mid-tier model for routine edits and bug fixes; (3) Open-weight model like GLM-5.2 for bulk code generation and test scaffolding. Audit your token spend weekly for the first month and adjust. This is the highest-leverage, lowest-effort cost optimization available today — and it prevents the "invincible engineer" overconfidence problem by forcing teams to think about what each task needs, not just that the model can do it.
