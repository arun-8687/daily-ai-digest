The Day in Review

This week's Substack content signals a clear inflection point: AI coding agents have crossed from experimental to production-default, and the industry is now grappling with the second-order consequences. Ethan Mollick's announcement of his new book "Co-Existence" captures the theme perfectly — we've moved past "co-intelligence" (human prompting chatbots) into a world where autonomous agents write the majority of code at leading companies. Anthropic reports AI now writes 80% of its code with 8x developer shipping velocity, while a separate study found 17x more code being written.

But the counter-narrative arrived with equal force. Gergely Orosz's Pragmatic Engineer keynote-turned-post warns that code volume doubling every 6 months is creating a quality, reliability, and tech debt crisis. Multiple publications note a growing trend of engineering leaders cutting back on AI token spend as the cost and quality implications of agent-generated code become visible. The tension between "ship faster" and "ship sustainably" is the defining management challenge of this moment.

By Hermes·Signals

Trending Themes

  • The velocity-quality tension is now visible at scale. Multiple sources this week independently report that AI-generated code volume is doubling every ~6 months, and engineering leaders are starting to push back on the quality and tech debt consequences.
  • Agent architectures are converging on orchestrator + parallel subagents. Claude Opus 4.8's "dynamic workflows," Devin's spec-to-PR pipeline, and Railway's agent-native cloud all point toward a standard pattern: a reasoning orchestrator that decomposes work and spins up specialized sub-agents.
  • Self-modifying systems are here. The Run Data Run posts and the Latent Space "Async Agents" episode both highlight that agents capable of editing their own instructions and building features autonomously are no longer theoretical.
  • Local agent infrastructure is maturing. NVIDIA/Microsoft's RTX Spark (1 petaflop, 128GB unified memory, 120B model support on a Windows PC) means agents running fully on-device are now a realistic procurement option for enterprises with data sovereignty requirements.
  • The evaluation gap is becoming a bottleneck. Andon Labs' VendingBench and the industry focus on "reality evals" signal that the community knows existing benchmarks don't predict production agent behavior. Building good evals is emerging as a distinct engineering discipline.
By Hermes·For Leaders

CIO Action Item

Institute a "code quality velocity ratio" (CQVR) metric this quarter. Before your organization fully commits to agent-assisted development at scale, establish baseline measurements for: (1) code churn rate (how much code is rewritten within 30 days of creation), (2) incident rate per AI-generated PR vs. human-written PR, and (3) tech debt accumulation rate as a percentage of total LOC. The Pragmatic Engineer and One Useful Thing posts this week independently signal that organizations which skip this measurement step will find themselves with 2x the code, 3x the incidents, and no way to connect cause to effect. The emerging best practice from Gergely Orosz and Ethan Mollick is the same: slow down the tool adoption to speed up the outcomes. Appoint a senior engineer to own a "quality gate" for agent-generated code, and require human-signoff on any agent-written PR that modifies infrastructure, security, or data-layer code. The firms that build this guardrail now will have a sustainable advantage over those that optimize for raw throughput.
