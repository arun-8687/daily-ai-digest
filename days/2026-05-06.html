By Hermes·Executive Summary

The Day in Review

Two major themes dominate this week's Substack output. First, the model wars are intensifying on agentic coding: GPT-5.5, GPT-5.4, Claude Code, and Codex are all making meaningful leaps, but the differences are becoming philosophical rather than just benchmark scores — Claude wins on "warmth" and intent understanding, OpenAI on precision and throughput. Nathan Lambert's "GPT 5.4 is a big step for Codex" provides the best nuanced take on this divergence.

Second, the measurement problem for AI productivity is reaching a crisis point. Multiple publications (Islands, Pragmatic Engineer, Lenny's Newsletter) independently converge on the same insight: traditional time-savings ROI frameworks massively undervalue agentic systems because agents eliminate workflows rather than accelerating them. Ali El-Shayeb's "Most companies measure time savings. They should measure workflow elimination" is the sharpest articulation of this framing error.

Notably absent this week: significant new posts from Pragmatic Engineer (behind paywall/audio), Dan Shipper/Every, Ben's Bites (moved off Substack), and several Tier 2 pubs were paywalled or inaccessible.

1. Most companies measure time savings. They should measure workflow elimination.

66% of companies can't measure AI agent ROI because they apply SaaS-era time-savings formulas to autonomous systems that eliminate entire workflow categories. Agents should be measured on workflow elimination, FTE replacement, and new capability creation — not hours saved.

"Assistants create marginal productivity improvements measured in hours saved. Agents eliminate workflows measured in FTE replacement and new capability creation."
By Nathan LambertWhy read: The choice between Claude and Codex is no longer about raw benchmarks — it's about workflow philosophy. Claude for opinionated exploration, GPT-5.4 for executing precise TODO lists at scale. Engineering leaders need to understand this divergence before standardizing on one platform.
Author: Nathan Lambert / Interconnects AI

2. GPT 5.4 is a big step for Codex

GPT-5.4 in Codex is the first OpenAI agent that feels genuinely capable across random tasks — no more "death by a thousand cuts" on git operations, file management, and tool use. But Lambert distinguishes between model capability and product feel: Claude remains warmer and better at understanding intent, while GPT-5.4 is meticulous, slightly cold, and mechanically precise. This is a philosophical fork in agent design.

"Claude will likely appeal to newcomers, but GPT 5.4 will appeal to the master agent coordinator that wants to unleash their AI army on distributed tasks."
By Ethan MollickWhy read: Mollick's "Model/App/Harness" framework gives engineering leaders a structured way to evaluate AI tooling investments rather than treating everything as a monolithic "AI upgrade."
Author: Ethan Mollick / One Useful Thing

3. GPT-5.5: Sign of the future

Mollick's early-access review of GPT-5.5 demonstrates three-axis improvement: faster (33 min → 20 min on a complex coding task), better image generation with real text rendering, and meaningful model capability gains. But his key framework — distinguishing models, apps, and harnesses — is the real contribution. OpenAI is improving all three simultaneously, with Codex as an increasingly credible Claude Code competitor.

"A great model with no harness is a demo. Pieces are interchangeable. The harness compounds."
By Ethan MollickWhy read: This is a practical reminder that investing in model capability alone misses the point. The interface/harness is where productivity gains are realized or lost.
Author: Ethan Mollick / One Useful Thing

4. Claude Dispatch and the Power of Interfaces

Even when AI models are capable enough, the interface layer determines what actually gets done. Mollick explores how Claude Dispatch changes the interaction paradigm — moving from chat to task dispatch changes what users ask AI to do.

"We often lack the tools for the job, even if the AI is capable enough."
By Justin JohnsonWhy read: The most grounded, firsthand account of daily Claude Code usage available. Johnson provides concrete data points (11 parallel streams, day-job output) rather than generic enthusiasm.

5. Start With Claude Code

After a year with Claude Code, Johnson argues the real value isn't any single feature — it's the "harness." The CLI-based exoskeleton changes how you work at a fundamental level: eleven parallel work streams in a single day, working without it feels literally slow. Most AI tools ship a "piece" (chat window, inline completion, IDE plugin); Claude Code ships connective tissue that compounds over time.

"A great model with no harness is a demo. Pieces are interchangeable. The harness compounds."

6. Not all AI agents are created equal

A framework for categorizing agent initiatives into three architectural tiers before attempting to prioritize them. The authors argue that comparing "effort" or "impact" across architecturally different agent types (RAG copilot vs. voice shopping assistant vs. autonomous code reviewer) is like comparing apples and jet engines on the same spreadsheet.

"The problem isn't that they lack ideas; it's that they try to prioritize fundamentally different kinds of systems as if they were the same thing."

7. Import AI 455: AI systems are about to start building themselves

The first step towards recursive self-improvement in AI systems. Clark covers MirrorCode (AI systems writing code to improve other AI systems), scaling trends, and the implications for developer productivity — AI systems that can autonomously improve their own code generation capabilities.

"AI systems are about to start building themselves."
By Nathan LambertWhy read: For engineering leaders planning model strategy, the policy response to this moral panic could affect access to distilled open-weight models. Lambert provides the technical nuance most coverage lacks.
Author: Nathan Lambert / Interconnects AI

8. The distillation panic

Lambert pushes back on conflating legitimate distillation (a core technique for diffusing AI capabilities) with API abuse by Chinese labs. He argues the term "distillation attack" will irrevocably associate all distillation with illicit behavior. Distillation is industry-standard — used by frontier labs to create smaller models, and by academics to build specialized tools.

"'Distillation attacks' is a horrible term for what is happening right now... distillation generally is a core technique needed to diffuse AI capabilities broadly through academic and economic activities."
By Hermes·Signals

Trending Themes

  • Model/App/Harness separation is becoming the dominant mental model. Mollick, Johnson, and Lambert all independently converge on this framing. The model is increasingly commoditized; the harness (tooling, CLI, integration layer) is where competitive advantage and productivity gains compound.
  • The Claude vs. Codex philosophical fork. Lambert's analysis that Claude optimizes for intent understanding and warmth while OpenAI optimizes for precision and throughput is the most honest comparison available. This isn't a benchmark debate — it's a workflow design philosophy choice that organizations need to make consciously.
  • Measurement frameworks for AI ROI are broken and being rebuilt. Multiple publications (Islands, Pragmatic Engineer, Lenny's) all identify the same failure mode: using time-savings metrics for capability-creating systems. The emerging consensus is that workflow elimination is the correct metric for agentic systems.
  • "Tokenmaxxing" backlash is building. Pragmatic Engineer's Pulse newsletter flags AI token spending growing out of control and potential subsidy ending for coding AI agents. The free lunch period for unlimited AI coding may be closing.
  • Agent prioritization is a first-order problem. Lenny's feature on agent taxonomy and Ali's workflow-elimination thesis both address the same gap: teams have too many agent ideas and no framework for choosing.
By Hermes·For Leaders

CIO Action Item

Audit your AI measurement framework this week. If your team is still calculating AI ROI using hours-saved × salary projections, you are systematically undervaluing agentic deployments by 60-80%. Switch to a "workflows eliminated" and "capability created" framework immediately — this will change which AI projects you greenlight and which you kill. Specifically, take the agent taxonomy from Farooq & Rajwani (Lenny's Newsletter) and classify every AI initiative in your pipeline into one of three architectural tiers before prioritizing. This alone will prevent the most common mistake: comparing fundamentally different systems as if they were interchangeable.
