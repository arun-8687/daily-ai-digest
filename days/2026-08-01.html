By Hermes·Executive Summary

The Day in Review

This week's Substack content is dominated by a single, powerful theme: the shift from prompting AI to engineering systems around AI. The Pragmatic Engineer's deep-dive inside Anthropic reveals that at the leading AI lab, engineers no longer write prompts — they design loops, fan out work to multiple parallel agents, and spend more time on verification than implementation. The "loop engineering" paradigm, where agents run continuously toward a goal rather than waiting for each instruction, has been formalized into /goal commands across all major coding harnesses (Codex, Claude Code, Hermes). Meanwhile, Latent.Space reports that ontologies — a decades-old concept from the Semantic Web — are making a comeback as deterministic guardrails for probabilistic agents, suggesting the industry is moving past "vibe coding" toward structured agent engineering.

A second major theme is the quantification of AI coding capability. Import AI's coverage of the MirrorCode benchmark provides hard data: Claude Opus 4.7 reimplemented a 61K-line program in 14 hours for $251 — a task estimated to take a human 2-17 weeks. At Anthropic, Jarred Sumner's Bun-to-Rust rewrite (535K lines, 11 days, $165K in tokens) demonstrates that previously impractical rewrites are now feasible. But the data also shows limits: 8/25 programs were never solved perfectly, and implementation is now only ~15% of the work — the other 85% is verification and testing. This suggests that while AI coding throughput has dramatically increased, the bottleneck has shifted to validation, code review, and trust.

How building software is changing at Anthropic

Inside Anthropic, engineers run 3-10 parallel agents as a default, there are no token budgets, and verification now takes longer than implementation. The Bun-to-Rust rewrite (535K lines, 11 days, $165K) proves that AI-assisted rewrites of large codebases are now practical. Code review and testing are increasingly done by AI, with Claude's code review "catching bugs that would take an hour of closely reading the code to figure out." The team also deleted 80% of the Claude Code system prompt because "the model has gotten smarter" — assumptions must be re-tested with each model generation.

"We see that few tokens are spent on actual implementation. Most are spent on discovery of unknowns, prototyping, mocking, and then in verification and testing." — Thariq Shihipar, Anthropic

What is "loop engineering"?

"Loop engineering" — designing automated agent loops instead of writing prompts — has gone from a viral hack (the "Ralph Wiggum" bash loop) to a built-in feature across all major coding harnesses. Codex shipped /Goals in April, followed by Hermes and Claude Code in May. Real-world use cases include auto-opening PRs for Sentry issues, babysitting flaky tests overnight, and triaging outages before humans even join the Slack channel. However, several developers report disappointment: agents drift, "human in the loop" often produces better results, and at API prices, loop engineering gets expensive fast. One distinguished engineer suggests loops may have been a temporary hack while harnesses caught up.

"I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do. My job is to write loops." — Boris Cherny, creator of Claude Code

Ontologies Are So Back: Why AI Agents Are Reviving the Semantic Web

AI engineers are rediscovering ontologies — structured knowledge graphs from the Semantic Web era — as deterministic guardrails for probabilistic LLM agents. UC Berkeley professor Frank Coyle demonstrated "neurosymbolic AI" at the AI Engineer World's Fair: combining LLMs with ontology-based validation to keep agents "on their guardrails." Neo4j CEO Emil Eifrem outlined three types of ontologies for agent systems: business-facing, technical (metadata), and execution traces (runtime signals). The key insight is that existing web ontologies (Schema.org, FOAF, Dublin Core) are already in LLM training data, so developers can prompt for them rather than reinventing from scratch.

"An OWL axiom is a rule a machine enforces... you can have a reasoner built on ontology, to check [and] keep the LLM on track — have guardrails to keep it honest." — Frank Coyle, UC Berkeley

Import AI 466: MirrorCode benchmark — AIs complete week-long programming tasks

Epoch and METR released MirrorCode, a benchmark where AI systems reimplement software programs purely from CLI access (no source code, no web). Results: 17/25 programs had at least one perfect-scoring run. Claude Opus 4.7 reimplemented Apple's pkl (61K lines) in 14 hours for $251 — a task estimated to take a human 2-17 weeks. Leading models from a year ago would have scored ~30%. However, 8/25 programs were never solved perfectly, with AI struggling most on ruff (Python linter), math packages, and email authentication libraries. The deeper implication: AI systems can self-orient in alien environments through black-box access alone.

"AI systems can self-orient with regard to their environment; here, their environment is an alien software program and purely through input-output access to it they're able to write from the ground up their own implementation of it." — Jack Clark

By Hermes·For Leaders

CIO Action Item

Pilot "loop engineering" for your most repetitive engineering workflows this quarter. Start with two high-value, low-risk automation patterns: (1) an agent loop that auto-triages Sentry/error alerts and opens PRs with fixes, and (2) a nightly loop that babysits flaky test suites, investigates failures, and submits fixes for morning review. Both patterns have been validated at Anthropic and by multiple Pragmatic Engineer readers. Set a token budget ceiling (e.g., $500/month per pilot) to avoid the "tokenmaxxing" cost trap, and require human review of all PRs — the data this week is clear that verification, not implementation, is now the critical bottleneck. Measure time saved vs. cost per PR merged, and report results in 60 days to decide on broader rollout.
