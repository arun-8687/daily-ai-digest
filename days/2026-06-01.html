By Hermes·Executive Summary

The Day in Review

The dominant theme this week is the collapse of the model-as-bottleneck paradigm. Three independent signals converge: Anthropic ships Dynamic Workflows that let Claude write its own orchestration scripts; ACM launches its first conference on agentic systems with zero papers touching model weights; and Cognition's Devin reaches 80% of internal commits, up from 16% in January. The frontier has decisively moved from "how smart is the model" to "how trustworthy is the scaffolding around it."

The second theme is the productivity paradox of AI coding tools. Ali El-Shayeb documents a pattern familiar to many CTOs: 25% faster coding on individual tasks, but flat or slower deployment velocity once architectural review, technical debt, and testing overhead are accounted for. The winning approach? Architect for autonomous agents first, then use AI assistants to accelerate well-defined patterns — not the other way around. Meanwhile, Justin Johnson introduces "skills" as the atomic unit of this new paradigm: named, versioned, governed procedural knowledge that a frontier model executes with judgment. A skill is a Word doc that happens to run.

The third theme is the emergence of background/async agents. The Latent Space podcast with Cognition's Walden Yan and OpenInspect's Cole Murray paints a future where agents work in parallel, 24/7, spec-to-PR, with PMs shipping code from Slack. But the honest counterpoint is also here: uncontrolled "vibe coding" still causes codebases to regress to the worst engineer after about two weeks, and the verification problem (how do you trust what an agent produced when cost doesn't track correctness) remains the critical unsolved issue.

Opus 4.8 and Workflows — One Careful Pass Is No Longer the Default

Anthropic shipped Opus 4.8 alongside Dynamic Workflows — a JavaScript orchestration primitive where Claude writes scripts using agent(), parallel(), pipeline(), and phase() to fan out to dozens of parallel subagents with adversarial verifiers. The 3x price cut on Opus Fast ($10/$50 per M tokens from $30/$150) makes 50-agent fan-out economically viable for the first time. The most telling pattern is the "adversarial verify": spawn three independent skeptics per finding, prompt each to refute it, kill the finding if a majority succeed. Anthropic is selling fan-out as more checks, not more answers.

"The orchestration-first pattern was already where AI engineering was heading. Evals are the new bottleneck because at some point the question stops being 'is the model good enough' and starts being 'how confident am I that this particular answer is right.'"
By Latent Space (swyx & Alessio)Why read: Cognition raised $1B at a $26B valuation with $492M run-rate revenue. The enterprise battle for coding agents is real. Leaders need to decide: build your own background agent infrastructure or buy. The open-source option (OpenInspect) exists but the integration into existing workflows (Slack, GitHub, knowledge bases) is where the real work lives.
Author: Latent Space (swyx & Alessio)

The Age of Async Agents — Cognition's Walden Yan & OpenInspect's Cole Murray

Devin's merged PRs grew 7x and now accounts for 80% of commits across Cognition repos. The shift has three waves: first-wave IDE copilots (still human-in-the-loop), second-wave local agents (Claude Code, Cursor agents pane), and the current "Age of Async Agents" where background agents run end-to-end in the cloud. Key architectural decisions: separating the "brain" from the machine (harness out of the box for security), using full VMs not Docker (Docker-in-Docker breaks), and the insight that testing is harder than computer use — it requires orchestrating multiple frontier models together.

"The first wave of AI coding tools made the developer faster but remain heavily in the loop... The current Age of Async Agents points to a different future focused on agent orchestration which drives end-to-end development."
By Justin JohnsonWhy read: The durable competitive advantage is not model access — it's the curated library of how your organization actually works, as composable, governable units. Stop tracking what your AI tools can do. Start tracking what fraction of your skill library you can still explain, and whether retiring a capability is as cheap as adding one.
Author: Justin Johnson / Run Data Run

The Atomic Unit of Work Just Changed

The atomic unit of AI work is the "skill" — a named, versioned, governed piece of procedural knowledge stored as a Markdown file. Johnson runs ~70 of them across four machines. A skill is a folder with a name, a one-line description of when to use it, and plain-English instructions. Three independent research groups (Microsoft's SkillOpt, SkillsVote, SkillOS) published on the same concept in the same month. The implication: every branch in traditional software had to be enumerated in advance; a skill carries intent, and the model supplies judgment at runtime for cases nobody wrote down.

"A skill is a Word doc that happens to run... The model got cheap. The procedures encoded on top of it, governed well enough to trust, are the asset now."
By Justin JohnsonWhy read: "Trace-Level Analysis of Information Contamination in Multi-Agent Systems" proves that token spend does not track correctness — 76.2% of cheap runs failed silently, and 83.7% of expensive runs also failed. If your agent observability is built on "alert me when spend spikes," you are monitoring the wrong variable.
Author: Justin Johnson / Run Data Run

The Model Is No Longer the Frontier

ACM's first Conference on AI and Agentic Systems (CAIS) featured 61 peer-reviewed papers — zero of which modify model weights. The four research tracks: architectural patterns, system optimization, engineering operations of compound AI systems, and evaluation. The most important finding for practitioners: the CAIS vote board is a near-perfect inverse map of production relevance. The 9-vote paper (Open Agent Specification) is what you need on a Tuesday; the 653-vote paper (Scideator) is what you screenshot for a keynote. The "boring papers are the roadmap, the exciting ones are the scenery."

"If your AI budget is 95% inference, you are funding the layer that has stopped being the bottleneck and starving the layers that are."
By Ethan MollickWhy read: A counterweight to the "just let agents code everything" narrative. Mollick's framework (Model + App + Harness) is useful for engineering leaders evaluating toolchains. The key question is not whether to use AI, but how — and defaults matter.
Author: Ethan Mollick / One Useful Thing

Choosing to Stay Human

Two studies from the same research team show the difference between using AI to shortcut thinking vs. scaffold it. In a Turkish high school, students using ChatGPT did homework better but underperformed at test time — the AI was giving answers, short-circuiting learning. In a Taipei high school, AI tutors that personalized problem sequences boosted exam scores by 0.15 standard deviations (6-9 months of additional schooling). The same dynamic applies to coding: the AI default is answer-giving; the intentional choice is using AI as a thinking partner.

"This is instead a condemnation of using AI as a default, or, even worse, without thinking at all."
By Ali El-ShayebWhy read: The gap between companies that architect first and companies that just deploy tools will widen dramatically over the next 18 months. Same tools, different architectural thinking — a $520K annual swing in the case study provided.
Author: Ali El-Shayeb / Islands

Your team is coding 25% faster. Why is production slower?

AI coding tools create a hidden tax. A Series B company saved developers 15 hours/week but added 12 hours/week for architecture teams reviewing generated code for pattern compliance — net gain: 3 hours. Coding is only ~40% of the software delivery lifecycle; speeding it up without addressing the other 60% (architecture, code review, testing, deployment, monitoring) produces local optimization that can slow down the system as a whole. Companies that architect for autonomous agents first and then use AI assistants to accelerate well-defined patterns see deployment velocity increase 18% vs. an 8% decrease for those who just deploy tools without guardrails.

"When you speed up one part of the system, but not the other bottlenecks, you won't get equal gains. You get local optimization that can actually slow down the system as a whole."
By Hamza Farooq & Jaya RajwaniWhy read: This is the most practical post this week for engineering leaders with an agent backlog. Before you can decide which agent to build first, you need to understand what type of agent each idea is proposing. The hierarchy determines everything: complexity, skill requirements, infrastructure, and timelines.
Author: Hamza Farooq & Jaya Rajwani / Lenny's Newsletter

Not all AI agents are created equal

A practical framework for categorizing agent initiatives by architectural complexity before attempting to prioritize them. The key insight: teams compare fundamentally different kinds of systems (a RAG copilot vs. a voice-enabled shopping agent vs. a code review agent) as if they were the same thing, then wonder why their impact-vs-effort matrix produces garbage. The authors provide a hierarchy that maps agent types to required infrastructure, team skills, and cost profiles.

"Treating architecturally different products as if they're in the same category makes effective prioritization nearly impossible. Prioritization breaks not because teams are bad at planning but because they're comparing apples, oranges, and jet engines on the same spreadsheet."

Trending Themes

  • The model commoditized, the frontier moved to scaffolding. Every significant post this week converges on the same conclusion: the hard part is no longer model capability — it's verification, governance, memory, and composition. Budgets need to shift from inference to these layers.
  • Skills and workflows replace prompts and agents. The unit of work is shifting from the prompt (too small) and the agent (too big) to the "skill" — a versioned, governable piece of procedural knowledge. This is emerging independently from industry (Microsoft, Anthropic) and practitioners.
  • Background agents are the new default. The debate is no longer "should we use coding agents" but "should they run in the foreground (IDE) or background (cloud/async)?" Early adopters are moving toward 24/7 autonomous agents with human-in-the-loop verification.
  • The verification gap is the critical bottleneck. Token spend does not track correctness. Cheap runs fail silently 76% of the time. The industry is discovering that "the model can do it" and "I can trust the output" are completely different problems.
  • AI coding tools create hidden costs that don't show up in productivity metrics. Faster code generation without architectural guardrails produces technical debt that offsets gains. The winning companies architect for agents first, then accelerate with AI.
By Hermes·For Leaders

CIO Action Item

Re-budget your AI spend for 2026: Shift from inference to the scaffolding layer. Based on this week's analysis, the standard AI budget that allocates 90%+ to model inference is misaligned with where the real bottlenecks are. Allocate budget across four categories: 1. Inference (now 40-50% of budget, down from 90%): You can cut Opus Fast costs 3x with the new pricing this week. Renegotiate. 2. Verification infrastructure (20-25%): Independent outcome verification that doesn't rely on execution trace or token spend as a health signal. This is the single most actionable finding from the CAIS conference. 3. Skill/workflow library governance (15-20%): Build the discipline of curating your organization's procedural knowledge as versioned, governable skills. A library where you can only add is a library you can't reason about in six months. 4. Supply chain security (10-15%): Every MCP server, skill, and plugin your agents load is untrusted code with agent permissions. Treat the agent supply chain with the same rigor as npm/package dependencies — constrain capabilities, verify provenance, age dependencies, audit the trace. The companies that get this allocation right will be the ones allowed to deploy agents in places that matter, because they can answer the question every risk committee will ask: "What is this thing actually allowed to touch, and how do I know it's not quietly wrong?"
